<objective>
## Goal
`pwvault merge OTHER.kdbx` merges another copy of the vault into this one the way KeePassXC's merge does: entries and groups matched by UUID, the newer version wins and the older one is kept in history, moves and deletions carry over. `--dry-run` reports the changes without saving.

## Purpose
Core value is "one encrypted local vault that I control … still open it in KeePass-compatible apps". People sync the vault file between devices (Syncthing, Nextcloud); when both copies change, today one side's edits are lost or `_write()` refuses the save. Merge makes two-device use safe without a server and without leaving KDBX.

## Output
- `merge_vaults()` and `MergeReport` in pwvault.py; `Vault.load_other()` helper to open a second file read-only
- Permanent deletes now record `DeletedObjects` (as KeePassXC does), so a deletion on one device survives a merge
- `pwvault merge` CLI subcommand
- tests/test_merge.py, including an interop test against keepassxc-cli (skipped when it is not installed)
- README and CHANGELOG entries
</objective>

<acceptance_criteria>

## AC-1: Edits on both sides survive
```gherkin
Given copies A and B of the same vault
  And entry X was edited only in A, entry Y only in B, and entry Z in both (B later)
When I run `pwvault merge B.kdbx` on A
Then X keeps A's version, Y gets B's version, Z gets B's version
  And Z's history holds A's version of Z (no version lost), capped at HISTORY_MAX
  And B.kdbx is byte-for-byte unchanged
```

## AC-2: New entries and groups are added in the right place
```gherkin
Given B has a new entry inside a new group (and a nested group) that A lacks
When A merges B
Then A has the same groups (same UUIDs) and the entry in the same group path
  And attachments on the new entry and on its history versions open with the same bytes
  And a custom icon used by the entry is copied into A's metadata
```

## AC-3: Moves and deletions carry over
```gherkin
Given in B an entry was moved to another group, another was trashed, and a third was permanently deleted
When A merges B
Then A shows the move, the trashed entry in the recycle bin, and the deleted entry gone
  And an entry deleted in B but edited in A after that deletion is kept
  And permanently deleting an entry or group with pwvault (delete in bin, empty recycle bin) records it in DeletedObjects
```

## AC-4: Safe save and clear report
```gherkin
Given a merge with changes
When it finishes
Then the vault is saved once through Vault._write() (a backup of the pre-merge file exists)
  And the output lists counts and titles for added, updated, moved and deleted entries
When run with --dry-run
Then the same report prints and the vault file is unchanged
When the other file has different credentials
Then `--other-keyfile`/password prompt for the other file are used; `--same-credentials` skips the second prompt
When the other file is the same file as the vault, or the wrong password is given
Then it exits with a clear error and saves nothing
```

## AC-5: Same result as KeePassXC
```gherkin
Given keepassxc-cli is installed
When the AC-1/AC-3 scenario is merged by pwvault and, from the same inputs, by `keepassxc-cli merge -s`
Then both results have the same entries (UUID, title, username, password, URL, notes, group path, recycle-bin state)
  And the pwvault result opens in keepassxc-cli
```

<task type="auto">
  <name>Task 1: Record deletions and build the merge engine</name>
  <files>pwvault.py, tests/test_merge.py</files>
  <action>
    Research first (read, don't guess): KeePassXC's Merger.cpp (src/core/Merger.cpp, 2.8 branch) for the default "synchronize" rules, and the KDBX 4 XML for DeletedObjects, LocationChanged, binaries pool and CustomIcons. Note any rule that differs from the list below in the SUMMARY.

    Deletions:
    - Add `Vault._record_deleted(item)` writing `<DeletedObject><UUID>b64</UUID><DeletionTime>…</DeletionTime></DeletedObject>` under Root/DeletedObjects (create if missing), using the same time encoding pykeepass uses for Times (KDBX 4: base64 seconds since 0001-01-01).
    - Call it for every entry and group removed permanently: `delete_entry` in the bin, `delete_group` in the bin (the group and everything inside it), `empty_recycle_bin` (everything inside the bin). Record before removing.

    Merge (`merge_vaults(vault, other_kp) -> MergeReport`), modifying only `vault.kp`:
    - Groups first, parents before children: match by UUID. Missing → create with the same UUID, name, notes, icon, times under the parent with the same UUID (root maps to root; the other side's recycle bin maps to this side's, created if needed). Present → newer LastModificationTime wins for name/notes/icon; parent follows the side with the newer LocationChanged.
    - Entries: match by UUID. Missing → deep-copy the element (with History) into the matching group, unless DeletedObjects on this side has it with a DeletionTime at or after the entry's LastModificationTime. Present → if mtimes differ, the newer one becomes current; histories are the union of both histories plus the older current, deduplicated by LastModificationTime, sorted oldest first, trimmed to HISTORY_MAX. Equal mtimes → leave as is. Location follows the newer LocationChanged.
    - Binaries: when copying an entry (or history version) from the other file, copy each referenced binary into this vault's pool and rewrite the `Binary/Value Ref` ids. Never share ids between files.
    - Custom icons: copy referenced CustomIcon elements this vault lacks.
    - Deletions: union of both DeletedObjects (latest time per UUID). Then remove any entry here whose UUID is deleted with a time after its LastModificationTime; remove a deleted group only when it is empty after that. Record what was removed.
    - `MergeReport` holds lists of (title, group path) for added, updated, moved, deleted, and `changed` (bool).
    - Avoid: matching by title/URL (that is `merge_records`, for CSV import — leave it alone); calling `vault.save()` inside the engine (the caller saves); touching mtimes of merged items (keep the winning side's times, or the next merge flips them).

    Tests in tests/test_merge.py (reuse the `Base` helpers): build A, copy to B by saving the same `kp` to two files, then edit each with explicit mtimes. Cover every AC-1–AC-3 case, idempotence (merging B twice changes nothing the second time; merging A into B and B into A gives the same entries), and the DeletedObjects recording.
