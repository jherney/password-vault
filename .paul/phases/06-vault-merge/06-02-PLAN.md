<objective>
## Goal
Database > Merge… in pwvault-gui merges another copy of the vault into the open one with the 06-01 engine: choose the file, give its credentials (or reuse this vault's), see the list of changes, then **Save** (one backed-up save) or **Discard** (the open vault goes back to what is on disk).

## Purpose
Most people use the GUI. Merging a Syncthing/Nextcloud conflict copy should not need the terminal, and it should show what will change before anything is written.

## Output
- `open_other_copy()` in pwvault.py, shared by `cmd_merge` and the GUI (same-file refusal, credentials, read-only load, file-named errors)
- `MergeDialog` in pwvault_gui.py and a "Merge another copy…" item in the Database menu
- `App.reload_from_disk()` used by Discard
- tests/test_gui_merge.py (GUI, under Xvfb) and CLI regression tests still passing
- README and CHANGELOG lines
</objective>

<acceptance_criteria>

## AC-1: Merge from the GUI
```gherkin
Given the vault is unlocked in the GUI and another copy exists with changes (an edited entry, a new entry, a trashed entry)
When I choose Database > Merge another copy…, pick the file, keep "Same password and key file as this vault" ticked and press Merge
Then the dialog lists every change (added, updated, moved, deleted, with group path and title) and the totals
When I press Save
Then the vault is saved once (a backup of the pre-merge file exists), the entry list shows the merged entries, the status bar says what was merged, and the other file is unchanged
```

## AC-2: Discard leaves the vault as it was
```gherkin
Given the change list is showing
When I press Discard, press Escape or close the window
Then nothing is saved, the vault file is byte-identical, and the open vault shows the same entries as before the merge (reloaded from disk without asking for the password)
```

## AC-3: Other credentials and errors
```gherkin
Given the other copy has its own password and key file
When I untick "Same password…", enter its password, choose its key file and press Merge
Then the merge works as in AC-1
When the password is wrong, the file is the open vault itself (directly or through a symlink), the file is missing, or it isn't a KeePass file
Then the dialog shows the error inline, names the file where relevant, and changes nothing
When the other copy has no differences
Then the dialog says "Already up to date." and offers only Close
```

## AC-4: Safe around locking
```gherkin
Given the change list is showing and not saved
When the vault auto-locks (dialog hold time ran out) or I lock it
Then the merge is not saved and the next unlock shows the file as it is on disk
```

## AC-5: One path for CLI and GUI
```gherkin
Given `pwvault merge` and the GUI both open the other copy
Then both go through `open_other_copy()`, and the existing CLI merge tests pass unchanged
```
