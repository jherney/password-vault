<design>
## Decisions (user, 2026-11-05)
- Double-click (or the "Show entry" button) closes the report and selects the entry in the main window via `show_group(entry.group, select=entry)`. The user edits it there and reopens the report to re-check. No edit-on-top, no live re-check.
- Phase /cso moves to its own plan (08-03).

## Dialog
- `CheckDialog(Dialog)`, title "Check passwords". On open: `BreachStore()` if present (closed right after), `check_vault(app.vault, store)`. Runs on the Tk thread (a lookup is two small reads per entry).
- Summary line: "N of M entries flagged (B breached, R reused, W weak)", or "No problems found in M entries" when none.
- Treeview columns Title, Username, Group, Issues (e.g. "breached, reused"). A reused row's Issues also names the others: "reused with Mail, Forum". Rows in entry order; first row selected.
- No breach list: a muted note under the summary, "Breached passwords not checked: no breach list yet. Run `pwvault breach update` in a terminal (a one-time download of about 55 GB)." Reused and weak rows still shown. A damaged list shows its VaultError text the same way.
- Buttons: Close, "Show entry" (Accent, disabled with no rows). Return and double-click = Show entry; Escape closes (Dialog base).
- Never shows a password or a hash.
- Opened from Database > "Check passwords…" through `open_check()`, which does nothing when no vault is open (same guard as open_backups()). No new keyboard shortcut.
- Locking closes it (lock() already destroys every Toplevel).
</design>

<acceptance_criteria>

## AC-1: Report lists flagged entries
```gherkin
Given an unlocked vault with a breached password, two entries sharing a password, a weak password, a strong unique one, an empty password, and a breached one in the recycle bin, and a breach list built by `breach import`
When the user opens Database > Check passwords…
Then the report lists exactly the breached, both reused and the weak entries, each with title, username, group and issues, reused rows naming the other entries
And the summary line gives the flagged and checked counts
And no password appears in any label or row
```

## AC-2: Without a breach list
```gherkin
Given no breach list (or a damaged one)
When the user opens the report
Then reused and weak entries are still listed
And a note says breached passwords were not checked and how to download the list
And opening the report makes no network connection (socket creation patched to raise)
```

## AC-3: Jump to an entry
```gherkin
Given the report is open with a flagged entry in a subgroup
When the user double-clicks it (or selects it and presses Show entry or Return)
Then the report closes, the main window shows that entry's group with the search cleared, and the entry is selected and scrolled into view
```

## AC-4: Clean vault, lock, no vault
```gherkin
Given a vault with no flagged entries, the report shows "No problems found" and Show entry is disabled
And when the vault locks while the report is open, the report closes
And open_check() with no vault open does nothing
```

## AC-5: Looks right in both themes (human-verify)
```gherkin
Given the GUI in light and in dark theme
When the user opens the report on a test vault
Then labels, rows and the note are readable and laid out like the Backups dialog
```
