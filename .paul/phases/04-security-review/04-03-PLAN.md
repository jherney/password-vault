<objective>
## Goal
Run a QA pass over the CLI (`pwvault.py`) and GUI (`pwvault_gui.py`) as a user would, record each result, fix confirmed defects, and add regression tests for every fix.

## Purpose
Phase 4 requires "QA pass on CLI and GUI with regression tests". The security audit (04-01) covered trust boundaries; this plan covers functional edge cases in everyday use (data loss, wrong feedback, broken dialogs), which the security audit did not target.

## Output
- `tests/test_cli_qa.py` and `tests/test_gui_qa.py` with regression tests
- Fixes in `pwvault.py` / `pwvault_gui.py` only where a defect is confirmed
- `.paul/phases/04-security-review/04-03-QA.md`: every path tested, result, and fix reference

</objective>

<acceptance_criteria>

## AC-1: CLI paths checked on a scratch vault
```gherkin
Given a fresh vault created in a temp directory with a password and a key file
When every subcommand (init, import, export, list, get, totp, add, remove, trash, generate, passwd, backup, keyfile) is run with valid input and with the common bad inputs (wrong password, missing entry, missing file, empty name)
Then each result is recorded in 04-03-QA.md as pass or defect, with the command used
```

## AC-2: Confirmed CLI defects are fixed and covered
```gherkin
Given a CLI defect confirmed in AC-1
When it is fixed
Then a regression test in tests/test_cli_qa.py fails before the fix and passes after it
```

## AC-3: GUI paths checked headlessly
```gherkin
Given the GUI run under xvfb with a scratch vault
When the add/edit entry dialog, search, recycle bin, backups dialog, generator, change-master dialog and theme switch are exercised
Then each result is recorded in 04-03-QA.md as pass or defect
```

## AC-4: Confirmed GUI defects are fixed and covered
```gherkin
Given a GUI defect confirmed in AC-3
When it is fixed
Then a regression test in tests/test_gui_qa.py fails before the fix and passes after it
```

## AC-5: No data loss or vault corruption in any tested path
```gherkin
Given any QA path that writes the vault
When it runs
Then a backup exists for the write, and the vault re-opens with the same entry count
```

## AC-6: Full suite passes
```gherkin
Given all fixes and new tests in place
When `xvfb-run -a python3 -m unittest discover -s tests` runs
Then it exits 0 with no failures or errors, and the count is the baseline plus the new tests
```
