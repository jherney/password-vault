<objective>
## Goal
Make the install reproducible and the release metadata consistent: a hash-pinned lock file for every dependency, version 1.3.0, and a changelog.

## Purpose
F-15 (04-01 audit) was deferred to Phase 5 "before any publish workflow". A published package should install the same bytes that were tested. Reproducible installs are the precondition for trusted publishing in 05-03.

## Output
- `requirements.lock`: all runtime and build dependencies pinned with hashes
- CI installs from the lock file with `--require-hashes`
- `pwvault.__version__ = "1.3.0"`, `CHANGELOG.md` with a 1.3.0 entry
- `tests/test_release.py` checks that the changelog's latest version matches `__version__`
</objective>

<acceptance_criteria>

## AC-1: Lock file installs only hashed, pinned packages
```gherkin
Given a clean Python 3.12 virtualenv
When `pip install --require-hashes -r requirements.lock` runs
Then it succeeds and every installed distribution matches a pinned version and hash
```

## AC-2: CI installs from the lock file
```gherkin
Given the tests workflow
When it runs on any Python in the 3.10–3.14 matrix
Then dependencies come from requirements.lock with --require-hashes, not requirements.txt
```

## AC-3: Version is 1.3.0 everywhere the app reports it
```gherkin
Given the release commit
When `pwvault --version` runs
Then it prints "pwvault 1.3.0", and the top CHANGELOG.md entry is 1.3.0
```

## AC-4: Version and changelog cannot drift
```gherkin
Given a future commit that changes __version__ without a matching CHANGELOG.md entry
When the test suite runs
Then tests/test_release.py fails
```

<tasks>

<task type="auto">
  <name>Task 1: Generate a hash-pinned lock file and use it in CI</name>
  <files>requirements.lock, .github/workflows/tests.yml, README.md</files>
  <action>
    - Use pip-tools (installed only in a throwaway venv, never added to requirements.txt or pyproject) to compile `requirements.txt` plus the `cryptography` legacy extra into `requirements.lock` with `--generate-hashes`.
    - Do not hand-edit the lock file. Regenerate it with the same command written at the top of the file.
    - In tests.yml, replace `pip install -r requirements.txt` with `pip install --require-hashes -r requirements.lock`. Keep requirements.txt as the human-edited input list.
    - Note in README (Development section) how to regenerate the lock.
    - Avoid: a build backend or pip-tools as a runtime or build dependency; pinning by hand; changing pykeepass 4.2.0 or the lxml >= 6.1 floor.
    - Risk to record: pip-compile resolves for the Python it runs on. Pure-Python pins are the same on 3.10–3.14, but lxml has per-version wheels, so the hashes must cover every Python in the CI matrix. Verify the lock installs on each matrix version (or add the extra hashes with `pip-compile --find-links` as needed).
  </action>
  <verify>In a fresh venv per Python in the CI matrix: `pip install --require-hashes -r requirements.lock && python -c "import pykeepass, lxml"` succeeds; `grep -n require-hashes .github/workflows/tests.yml` matches.</verify>
  <done>AC-1 satisfied: lock installs with hashes on every matrix Python. AC-2 satisfied: CI uses the lock.</done>
</task>

<task type="auto">
  <name>Task 2: Bump to 1.3.0, write the changelog, and guard the pair with a test</name>
  <files>pwvault.py, CHANGELOG.md, tests/test_release.py</files>
  <action>
    - Set `__version__ = "1.3.0"` in pwvault.py (single source: pyproject already reads it dynamically).
    - Create CHANGELOG.md (Keep a Changelog format). 1.3.0 section lists the milestone: safe saves and versioned backups (Phase 1), TOTP codes (Phase 2), GUI polish: light/dark palette, Backups dialog, Ctrl+Shift+B (Phase 3), security review and QA fixes incl. export overwrite refusal, untitled-entry refusal, trash restore to original group, quit timer cancel (Phase 4), reproducible install (this plan). Keep entries to user-visible changes; no internal file names.
    - tests/test_release.py: parse the first `## [x.y.z]` heading from CHANGELOG.md and assert it equals `pwvault.__version__`.
    - Avoid: a version string in two places that the test does not compare; adding a changelog tool dependency.
  </action>
  <verify>`python3 -m unittest tests.test_release` (from repo root, or test_release from tests/) passes; `python3 pwvault.py --version` prints `pwvault 1.3.0`; temporarily set the changelog to 1.2.9 and confirm the test fails, then revert.</verify>
  <done>AC-3 satisfied: version and changelog agree at 1.3.0. AC-4 satisfied: the drift test fails when they differ.</done>
</task>
