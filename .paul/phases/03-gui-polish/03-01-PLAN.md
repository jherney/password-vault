<objective>
## Goal
The Tkinter GUI gets three improvements: a Backups dialog that lists the last versions of the vault and restores one, a palette that follows the desktop's light or dark setting, and visual and shortcut tidying within both palettes.

## Purpose
Core value: one encrypted local vault I control, usable from the GUI. Restoring a backup is currently CLI-only, so a GUI user who breaks their vault has to leave the app. The app is hard-wired dark, which clashes with light desktops.

## Output
- `pwvault_gui.py`: Backups dialog, theme detection and two palettes, spacing and shortcut changes
- `tests/test_gui_polish.py`: new tests (theme detection, backups dialog, shortcuts)
- `README.md`: shortcut table and a short note on theme and backups
</objective>

## Key facts established during planning
- Tk 9.0 on Linux has no appearance query (`tk appearance` is unknown), so the theme must be read from the desktop settings.
- This machine runs KDE. `~/.config/kdeglobals` `[Colors:Window]` `BackgroundNormal=239,240,241` (light). gsettings `color-scheme` here returns `prefer-light`, but gsettings isn't the KDE source of truth, so it's only a fallback.
- The palette constants are read when widgets are built, so the theme is chosen once at startup. Live switching isn't needed for this plan; a theme change takes effect on next launch.
- Already present, do not rebuild: search across all groups (Ctrl+F, `refresh()` traces the search variable), Ctrl+C/B/T/N/L.

## AC-1: Restore a vault from a backup in the GUI
```gherkin
Given an open vault with at least one backup
When I open Database > Backups (or press Ctrl+Shift+B)
Then a dialog lists the backups newest first, with the time each was made
And choosing one and clicking Restore asks for confirmation first
And after confirming, the vault file is the chosen backup (checked by reopening it) and the GUI reloads its entries
And a backup that won't open with this vault's key shows an error and changes nothing
And with no backups, the dialog says so and the Restore button is disabled
```

## AC-2: Palette follows the desktop theme
```gherkin
Given the desktop's window background is light (KDE BackgroundNormal luminance above 50%, or GNOME color-scheme prefer-light)
When the GUI starts
Then it uses the light palette
And when the setting is dark, or cannot be read (no KDE file, no gsettings, unparsable value), it uses the dark palette (today's look)
And the detection uses the standard library only (no new dependency)
And the palette is chosen once at startup; a changed desktop setting applies on next launch
```

## AC-3: Both palettes stay readable and shortcuts are complete
```gherkin
Given either palette
When I use the list, detail panel, dialogs and strength meter
Then body text, muted text and the selected row meet readable contrast (the muted text in the light palette is at least 4.5:1 against its panel)
And Ctrl+Shift+B opens the Backups dialog, and README's shortcut table lists it
And the existing shortcuts (Ctrl+C/B/T/N/F/L) behave as before
```

    - Add `BackupsDialog(Dialog)` modelled on `HistoryDialog`: a Treeview of `pwvault.list_backups(app.vault.path)` (time column, file name), newest first, with a Restore button and Close.
    - Restore: take the selected backup, ask `messagebox.askyesno` ("Replace the current vault with this backup? The current file is kept as a backup.") and on yes call `app.vault.restore(path)`. Catch `VaultError` and show it in the dialog's error label, changing nothing. On success, close the dialog, then reload the vault from disk the same way the GUI does after an external change (reuse existing unlock/load code paths; do not re-implement them).

    - Avoid: writing or copying backup files in the GUI; calling `Vault.restore` with anything but a path from `list_backups`; a restore without the confirmation.
    Tests (display-only, same skip guard as the existing GUI tests): listing order and empty state, a successful restore of a built backup (vault bytes equal the backup afterwards), a wrong-key backup refused with the vault unchanged.
  </action>
